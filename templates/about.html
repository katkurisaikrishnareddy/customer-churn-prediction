🧭 How this system works

  1. Data — IBM Telco Customer Churn (7,043 customers, 21 columns, 26.5% churn). Automated quality gate before training.
  2. Split first — stratified 80/20 train/test; scaling and encoding live inside the Pipeline, so nothing leaks from the test set.
  3. Features — cleaned TotalCharges (new customers = $0), plus business features (add-on count, auto-pay, month-to-month, tenure bucket, price-change ratio). Gender is excluded.
  4. Models — Logistic Regression, Random Forest, HistGradientBoosting, XGBoost tuned with 5-fold stratified CV on PR-AUC; the simplest model within one standard error of the best is chosen.
  5. Imbalance — class weights and SMOTE were tested: they improve recall but not ranking quality, so we keep probabilities clean and move the threshold instead.
  6. Threshold — chosen from retention economics (offer cost vs. revenue saved), using out-of-fold predictions only.
  7. Explainability — SHAP for the global view; a what-if factor analysis for each individual prediction.
  8. Deployment — Flask + gunicorn + Docker; JSON API, CSV batch scoring, health check, automated tests, CI.

⚠️ Limitations

  • One public dataset from one point in time — retrain on current company data before real use.
  • Business numbers are illustrative assumptions (edit config.yaml).
  • Predictions show association, not causation; suggested actions are a playbook, not proof an offer will work.
  • The model flags seniors more often — human review required.
